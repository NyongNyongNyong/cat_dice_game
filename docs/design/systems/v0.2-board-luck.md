## Phase A — 보드 + 배치

### A1. 보드 모델 (`RunManager`)

| 상수 | 값 |
|------|-----|
| `BOARD_COLS` | 4 |
| `BOARD_ROWS` | 3 |
| `BOARD_CELLS` | 12 |
| `STARTING_UNLOCKED_SLOTS` | 4 |
| `MAX_OWNED_DICE` | 8 |

- `unlocked_slots: int` — 해금된 칸 수 (시작 4, 최대 12). 해금 순서는 `BOARD_UNLOCK_ORDER` (시작 시 가운데 행 칸 4~7).
- `board_placement: Array[int]` — 길이 12. 각 칸에 배치된 **보유 주사위 index** 또는 `-1`(빈칸).
- 보유 주사위는 최대 8개 (`MAX_OWNED_DICE`). 시작 4개 (`starter_loadout.json`).

**API**
- `get_unlocked_slot_count() -> int`
- `unlock_next_slot() -> bool` — 비용·상점 연동은 **미정**(§11). 구조만 제공, 호출부 없음.
- `place_die(owned_index, cell) -> bool` — 해금 칸에만, 같은 주사위 중복 배치 방지.
- `clear_cell(cell) -> bool`
- `get_placed_owned_indices() -> Array[int]` — 칸 순서대로 배치된 보유 index (빈칸 제외).
- `get_placed_dice() -> Array[Resource]` — 위 index의 주사위 리소스.
- `get_placed_count() -> int`

### A2. 배치 → 굴림 플로우

```
주사위 배치 (보드)  ← 굴리기 전, IDLE
    ↓
굴림 (배치된 주사위만)
    ↓
주사위 효과 처리
    ↓
족보 계산
    ↓
점수 계산
```

- `RoundController.dice_resources`에 **배치된 주사위**만 주입 → 기존 굴림·족보·점수 로직 재사용.
- 배치 0개면 굴림 불가.
- 위치(빈칸) 효과는 **미정**(§11) — 이번엔 빈칸은 점수에 기여하지 않음.

### A3. UI (`run_scene`)

- **보드:** 3행×4열 `GridContainer` (`columns=4`), 칸 = `DiceSlot`. 해금 칸만 활성, 잠금 칸은 흐리게.
- **로스터 트레이:** 아직 배치 안 한 보유 주사위 목록.
- **배치 — 클릭(구현됨):** 트레이 주사위 선택 후 보드 칸 클릭. 배치된 칸 클릭 시 회수.
- **배치 — 드래그(구현됨):** `DiceSlot`에 `slot_kind`("board"/"tray") + `slot_dropped` 시그널.
  - 트레이 주사위 → 보드 빈 칸: 배치 (`place_die`).
  - 보드 칸 → 보드 칸: 빈칸이면 이동, 점유칸이면 두 칸 교환 (`move_placed`).
  - 보드 주사위 → 트레이 칩: 회수 (`clear_cell`).
  - 보드 주사위 → **유효 슬롯이 아닌 곳(빈 공간·잠금 칸 등)**: 드롭 실패로 판정(`Viewport.gui_is_drag_successful()`)해 `dropped_outside` → 배치 해제(트레이 회수). 트레이가 비어 대상 칩이 없어도 이 경로로 회수 가능.
  - 배치된 주사위 **짧게 클릭**은 제거 유지, **누른 채 드래그**는 이동(클릭 판정은 release 시점).
  - 편집 가능(`_can_edit_board`: run 진행·레버 정지·IDLE/READY)일 때만 드래그 활성 (`_sync_ui`에서 갱신).
- 굴림 트리거는 배치된 주사위 대상.

## Phase B — 행운 (구현됨)

### B1. 행운 결과 선택 (`LuckResolver`) — 구현 정본

GDD §4.3. **남은(미확정) 주사위는 최대 `ENUM_DICE=4`개**만 `6^k` 전수 계산(샘플링 없음).

1. 배치된 주사위 중 `ENUM_DICE`개를 무작위로 골라 전수 대상으로, 나머지는 즉시 랜덤 확정.
2. 전수 대상의 모든 면 조합(`6^k`)마다 전체 면을 구성 → `RoundController.resolve_faces`로 값 해석 → `HandCalculator.evaluate().total_score`.
3. **행운 컷** (`luck` = `L`):
   - 컷 비율 `f(L) = CUT_FRACTION_MAX · (1 − 1/(1 + K·|L|))`, `CUT_FRACTION_MAX = 0.9`, `K = 5/120` (~0.0417).
   - `f(0)=0`, `f(30)≈0.5`, `f(10)≈0.27` — 로그 스케일, **0.9 점근 → 100% 안전 불가**.
   - `L > 0` → 하위 `floor(f·n)` 제거, `L < 0` → 상위 제거 (최소 1개 보존).
4. 남은 결과 중 무작위 1개 선택 → 그 면으로 확정.

> **밸런스 v1(튜닝 예정):** `CUT_FRACTION_MAX`, `K`, `ENUM_DICE`는 플레이테스트로 조정. `luck` 소스(주사위·유물)는 아직 없어 기본 `0` → 현재 굴림은 균등 무작위와 동일. UI는 행운 수치만 노출.

### B2. v0.1 제거 vs v0.2 유지

**제거됨 (폐기):**
- 주사위 **1개 리롤** — `RoundController._reroll_selected_die`, 선택 후 Roll 단일 재굴림.
- **골드 리롤** 경제 — `RunManager.can_afford_reroll/try_spend_reroll_gold`.
- v0.1 **칩=점수** 혼선 — GDD §10.3 참고.

**유지 (v0.2 정본, GDD §10.1):**
- **칩 = 층당 굴림 횟수** — 굴림 1회당 칩 1, `INITIAL_CHIPS=10`. Push Your Luck.
- **점수** — 족보 누적(`current_score`), 칩과 별개.
